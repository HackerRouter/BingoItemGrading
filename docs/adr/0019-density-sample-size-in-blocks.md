# 密度可信度按方块数判定，不按区块数

## 背景

采集侧给群系级密度打了一个 `reliable` 标记，判据是 `chunks >= minChunks`（默认 200 个实测区块），本项目的统计导入也沿用它给 `confidence` 定级，`reliable: false` 一律降为 `low`。

用这个标记去筛「哪个群系的挖掘代价可信」会出错。实测数据：

| 群系 | 区块数 | 方块数 | 每区块 | 上游 `reliable` |
|---|---|---|---|---|
| `lush_caves` 红石矿 | 12 | **2** | 10.04 | false |
| `wooded_badlands` 深层红石 | 20 | **289** | 42.04 | false |
| `badlands` 金矿 | 38 | **483** | 26.56 | false |
| `mushroom_fields` 深层红石 | 93 | **1811** | 36.91 | false |
| `savanna_plateau` 红石矿 | 236 | 258 | 3.32 | true |
| `beach` 红石矿 | 2404 | 1546 | 3.15 | true |

用 `reliable` 过滤会同时犯两个方向相反的错：把只数到 **2 块**的 `lush_caves` 和数到 **483 块**的 `badlands` 一视同仁地判为不可信。恶地金矿的富集是真实存在的地形特征（数据包里 `ore_gold_extra` 就是 badlands 专属），被过滤掉等于把最需要区分的稀有群系排除了——这正是 C9 描述的困境。

## 决策

**下游判断密度能否用来算代价时，看数到的方块数 `total_blocks`，阈值 `units.MIN_DENSITY_BLOCKS = 200`。**

密度是 `方块数 / 等效区块数`，比值本身的抽样误差由计数主导，相对标准误约 `1/√n`，`n` 是方块数。区块数只影响空间聚类带来的额外方差（矿脉在区块间不均匀），那是二阶效应。

200 这个阈值与上游 `minOreSamples` 的默认值一致，两边口径可以对照。上游其实已经把这两种可靠度分开设计：

- `reliable`（`chunks >= minChunks`）管密度，理由是「密度是区域平均量，需要足够的区块面积」。
- `reliableExposure`（`count >= minOreSamples`）管暴露率，理由是「暴露率是方块级概率，样本是方块数」。

本项目采用第二个口径判密度的可用性，与上游对第一个口径的设计意图不同。差异的实质：上游把区块数当密度的有效样本量，是因为假设矿脉聚类会让同区块内的方块高度相关；但聚类只放大方差，不改变估计的期望，而在只做群系间相对排序时，放大后的方差并不影响排序方向——除非样本小到方差压过差异，而方块数正是衡量这一点的量。

## 后果

- `MiningEstimate` 同时携带 `sample_blocks`（判据）、`density_trusted`（结果）、`chunk_reliable`（上游原值，仅记录）。三者都不丢，方便对照。
- 上游的 `reliable` 仍然决定 `confidence: low`。想按置信度筛的地方照旧可用；挖掘路径不用它。
- 恶地金矿的最优代价从「样本不足」变成可信值 20.6 TU（287 块样本），红石深层最优从 `snowy_beach`（31/55 群系参与）变为 `wooded_badlands`（53/55，289 块），参与比较的群系从 31 增至 53。
- 真正的极小样本（`lush_caves` 2 块、`sulfur_caves` 18 块）依旧被挡住。

## 验证

`tests/test_mining.py` 覆盖四种组合：区块少但方块多（可信）、方块少（不可信）、两者都缺（`None`）、区块多但方块少（不可信）。`tools/probe_density_samples.py` 打印三个矿种的样本构成，可用于复核阈值。

## 替代方案

**保持 `chunks >= 200`**：会排除恶地、山地等稀有群系，恰好是需要区分的对象，代价是这些群系的富集信息不可用。

**完全不设判据**：`lush_caves` 会以 2 块样本算出 8.8 TU 的红石代价并胜出，污染跨群系取最优。

# 相对时间单位与整数档位

> **后续修订**：TU 已改为 1 秒，档位边界与分数零点同比缩放，当前值见 `docs/data/units.md`。

## 背景

用真实秒数标定需要可信的计时数据，而计时数据随玩家、路线、设备漂移。同时，人工标注「这个物品多久能拿到」时给不出秒级精度，只会给「一会儿」「挺久」。

## 决策

内部统一用 TU（`1 TU ≈ 地表跑图 100 格`），输出前压成 0–20 的整数档位：

```
score = clamp(round(log2(cost_TU / cost_floor)), 0, 20)
```

人工标注只判档位，档内代表值由 `docs/units.md` 的几何中点定义给出。

## 后果

- 调参以档位为单位，一次调整至少影响一档；不足一档的调整视为噪声。
- 分数可跨地形包比较，因为零点由 `cost_floor` 固定，不用秒数。
- 档位映射是常量表，改它等于改整张分数表，需重新标定 anchor。

## 替代方案

直接输出 TU 浮点数：看似精度更高，但标定数据撑不起这个精度，且调参时无法判断 3% 的变化是否显著。

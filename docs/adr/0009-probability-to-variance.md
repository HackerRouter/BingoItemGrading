# 概率只进方差惩罚

> **后续修订**：概率数值已并入 `gamedata.PROBABILITY_ROWS`；战利品来源改用「每次触发的期望件数」（ADR 0027）。

## 背景

低概率来源（树叶掉木棍 5%、僵尸掉铁锭 2.5%）与确定性来源在「能不能拿到」上等价，在「要花多久」上不等价。把概率直接乘进代价会误导：概率低不等于距离远，且期望尝试次数与路径结构无关。

## 决策

- 来源的 `coverage` 保持 1.0，概率不在代价上二次打折。
- `probability` 映射到 `variance_penalty` 档位：

  | 概率 | 档位 |
  |---|---|
  | `p ≥ 0.5` | low |
  | `0.1 ≤ p < 0.5` | medium |
  | `p < 0.1` | high |

- 映射阈值由 `src/bingo_grading/units.py` 的常量给出，标定后可以改；`probability` 原值随诊断输出下传，供下游折算。
- 概率值来自 `data/knowledge/probabilities.toml` 手工登记。未登记的概率性来源按确定性处理，并在覆盖率报告里单列，不静默猜。

## 后果

- 概率低的来源不会因为「期望尝试很多次」而被抬到高分，只抬高方差档。
- 概率表的覆盖面是可见指标：未登记条目数随数据增长，构成待办清单。
- 人工标注 `variance_penalty` 时只判非概率来源，避免同一维度两套口径打架。

## 替代方案

把 `1/p` 乘进代价：树叶的 5% 会变成 20 倍代价，木棍的分数被推到与钻石同档，与实测经验不符。

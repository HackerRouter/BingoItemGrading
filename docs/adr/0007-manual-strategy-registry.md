# 链式策略人工注册、机器校验

> **后续修订**：`strategies/` 人工注册没有实施。任何物品都从来源索引自动拼图，入口是 `case/registry.py` 的 `builder_for()`。

## 背景

玩家的链式技巧（村庄铁匠铺 → 绿宝石 → 铁装、沉船 → 藏宝图 → 埋藏的宝藏）来自游戏经验，无法从数据包静态推出；但它们对难度的影响大于任何单条掉落。

## 决策

策略以 `strategies/` 下的声明式文件人工注册，声明落哪些槽位、前置事件、并联分支与共享前置。机器负责两件事：

- 校验：策略每个环节在地形包中是否实际可达（交易被禁、结构不生成、物品不存在），不可达标红。
- 聚合：把策略展开成 `path_node` / `edge`，与其他路径一起参与 DAG 计算。

自动推导只负责生成槽位候选与暴露盲区，不猜链式策略。

## 后果

- 新增策略是数据改动，不改引擎代码。
- 策略必须能追溯到具体来源（谁注册、依据什么），否则视为未完成。
- 策略与自动候选并列：策略覆盖的槽位仍保留自动候选，两者都参与聚合，不互相屏蔽。

## 替代方案

从配方与掉落自动组合出链式路径：组合爆炸，且大部分组合玩家不会走；人工注册的条目少而准，校验成本低。

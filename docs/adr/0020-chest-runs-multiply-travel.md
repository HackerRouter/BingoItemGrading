# 开箱路线要按「每箱产出」重复计次

## 背景

金锭的第一版 DAG 算出地表域只要 2.1 TU（约 15 秒）就能拿到一锭，比挖矿便宜 11 倍。这个数不对。

原因在开箱路线的计费方式。第一版把「跑一趟村庄 + 开神庙箱」当成一次性成本：

```
cost = 旅行 1 次 + 翻箱 1 次 + 开箱 1 次
```

但战利品统计给的是**每箱期望**，不是每趟保证。村庄神庙每箱只有 0.72 个金锭，一处村庄只有一个神庙箱——跑一趟拿不到一锭。

## 决策

开箱路线的代价乘上「要跑几处」：

```
runs = max(1, 1 / (每箱产出 × 每处箱数))
cost = runs × (旅行 + 翻找 + 开箱)
```

**旅行成本要一起乘。** 这是开箱与挖矿的根本差别：

- 挖矿：到达一次，然后在一个矿道里一直挖下去，挖够为止。旅行只付一次。
- 开箱：跑一趟，拿一点，**再跑去下一个地方**。每处都要重付旅行。

村庄神庙的实际数：每箱 0.72 锭、每村 1 个神庙箱 → 要跑 `1/(0.72×1) = 1.39` 处村庄。修正后地表域从 2.1 TU 变成 3.8 TU（两条开箱路线并联）。

## 后果

- 所有「每箱产出 < 1」的战利品路线都会被显著抬高，这符合直觉：稀有战利品不能靠开一个箱子拿到。
- 每箱产出 > 1 的路线不受影响（`max(1, ...)` 兜底），比如堡垒宝藏每箱 2.33 锭。
- 结构密度用的是**期望最近距离**，它本身已经隐含了「平均要跑多远才遇到一个」。乘上 `runs` 相当于「跑 `runs` 趟，每趟都从当前位置出发找下一个」，这比实际略保守（第二趟的起点已经离第一个结构更近了），但不影响数量级。
- 诊断输出里必须显示 `runs`，否则「为什么 3.8 TU」无法解释。

## 验证

`tests/test_case_gold.py` 的 `test_surface_branch_repeats_travel_when_chest_yield_is_low` 检查村庄链代价 > 5 TU，`test_surface_parallels_two_sites` 检查两条开箱路线确实并联。

## 替代方案

**只算一次旅行**：低估开箱路线，让它虚假地胜过挖矿，见上文的 2.1 TU。这个错误很难从输出里看出来，因为数字「看起来很正常」。

**每箱产出当概率**：把 0.72 锭/箱视为「0.72 概率拿到 1 锭」，会算出「期望 1.39 箱」，但忽略开箱本身的时间与跑图，仍然低估。

## 后续修正

本文最初以村庄神庙（0.72 锭/箱）为例。后来查清 `village_temple` 只存在于沙漠村庄的 `desert_temple_1`，改用 `minecraft:villages` 汇总行（0.0702 锭/箱），见 [ADR 0022](0022-village-loot-uses-summary-row.md)。runs 的公式不变，只是 `per_chest` 的来源换了。

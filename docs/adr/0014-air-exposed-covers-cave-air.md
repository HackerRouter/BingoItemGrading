# `air_exposed` 无法区分地表露头与洞穴内壁

## 背景

`ore_exposure` 把矿石分成空气暴露、水暴露、埋藏三类。`air_exposed` 的判定是「相邻方块是空气」，而空气集合是：

```
minecraft:air, minecraft:cave_air, minecraft:void_air
```

洞穴空气也算。

于是 `air_exposed_share` 高只能说明「这块矿石挨着某种空气」，不能说明「它在地表能直接捡到」。地下洞穴壁上的矿石与地表露头的矿石，在这个指标里是同一个值。

这个区别在多数物品上不重要，但在「被不透明地表覆盖的富集」上会算出完全相反的方向：

## 具体反例：恶地金矿

- 恶地地表是厚陶瓦，金矿被盖住，**不露出**。
- 恶地的金矿来自专属特性 `ore_gold_extra`：`count=50`，`y=32~256`（数据包可确证，仅恶地三变体引用）。
- 恶地的 `openSurfaceShare` 是 0.935（地表很开阔），但开阔的是陶瓦，不是金矿。
- 若用 `air_exposed_share` 判断，会得出「恶地金矿容易捡」——与实际相反，玩家必须挖。

## 决策

1. **`air_exposed_share` 不用于判断「能不能捡」**。它的正当用途是描述「地下开采时，矿石有多少已经在空气面上」——这影响挖矿时的实际挖掘量，不影响是否需要挖。
2. **群系级的矿石代价用 `ore_density`，不用暴露**。这也是 [ADR 0012](0012-biome-ore-density-without-exposure.md) 把两者拆开的原因之一。
3. **不新增「地表露头」字段**。要算它需要「该矿石上方到地表之间是否全为不透明方块」，这是逐方块查询，成本远高于现有三个判定；而它要回答的问题可以由「密度 × 纵段 × 地下空洞率」更直接地回答。

## 后果

- 恶地类群系的金矿不会被误判成「顺路可捡」。
- 但「挖起来有多贵」现在算不出来：缺纵段分解（`ore_density` 只有整柱平均）与地下空洞率。这两项已作为 C10 / C11 记入 [`collector-requirements.md`](../contracts/collector-contract.md)。
- `ore_exposure` 仍保留在维度级，含义收窄为「地下开采时已有空气面的比例」，文档已按此更新。

## 替代方案

**把 `cave_air` 从空气集合里去掉**：会让洞穴壁上的矿石全部变成「埋藏」，而实际上它们是最容易挖的——方向相反地错。且这个数还会被其它用途引用，改定义会波及全部下游。

**单独加一个 `surface_exposed` 字段**：见上文第 3 条，成本与收益不匹配。若日后纵段与空洞率数据到位后仍发现需要，再议。

# DAG 聚合的四个实现决定

## 背景

[ADR 0003](0003-multi-path-aggregation.md) 定下了聚合语义的骨架：域内按覆盖率加权并联、域间取 min。落到代码（`src/bingo_grading/graph.py`）时有四处需要具体化，而它们都会改变结果或改变诊断的可解释性。

## 决策

### 1. 没有 `group_id` 的边自成一组

`requires` 边通常只表达「这一步要先做那一步」，此时 `group_id` 留空。组内只有一个成员时，并联公式退化为 `1 / (1 / (cost / coverage)) = cost / coverage`，与链式相加一致。因此不需要为「链」和「并联」写两套代码路径。

### 2. 一个节点有多个组时，组间相加

多个不同 `group_id` 表示「这几件事都得办」。这是 AND 语义，代价相加。组内是 OR 语义，取并联。这两种语义在同一个节点上并存，是等式的两半，不是二选一。

### 3. 方差惩罚乘在节点上，且在域间取 min 之前

节点是「一个域内的一条完整方案」，也是最小的域聚合单位。把惩罚乘在节点上、再取 min，意味着不确定性大的方案会先被惩罚、再被别人比下去——这正是想要的：低概率来源不应该在取 min 时靠原始代价获胜。

概率性来源不额外打折代价（ADR 0009），只决定方差档。

### 4. 被并联的成员节点，`ref` 不设成目标物品

第一次跑红石案例时，挖矿节点和地牢节点的 `ref` 都写成了 `minecraft:redstone`。结果它们凭原始代价直接进入「跨域取 min」的候选池，把 `coverage` 完全绕过了——把地牢覆盖率降到 0.3，最终结果仍然是地牢的原始代价。

原因是把两种不同的东西混在了一起：

- **子路径**：「走到地牢并开箱」是地下域并联组里的一个成员，它的代价要参与并联。
- **完整方案**：「某域怎么拿到红石」是并联之后的汇合节点。

修正规则：成员的 `ref` 指向它自己拿到的东西（`minecraft:deepslate_redstone_ore`、`minecraft:monster_room`），只有汇合节点和独立成链的终点才用目标物品。这样候选池里只剩真正的域级方案，诊断输出也不会出现同一件事的两个数字。

## 后果

- 建图时必须想清楚「这个节点是子路径还是完整方案」，想错会静默得到错误的 min。
- 诊断输出里 `domain_candidates` 应当只有域级节点；出现多个同域候选通常说明 `ref` 写错了。
- 环检测用 Kahn 拓扑排序，稳定序（堆）保证同一张图两次输出一致，便于比对。

## 验证

`tools/show_redstone_dag.py` 与 `tests/test_case_redstone.py` 覆盖验收标准：地牢 `coverage` 从 1.0 降到 0.5 时，最优域从地下翻转为地表，地下并联代价单调上升并向单独挖矿的代价收敛。

## 替代方案

**并联改成取 min**：实现更简单，但会丢掉「两条路同时推进能更快」这一事实，且对 `coverage` 完全无感——`coverage` 就退化成一个死参数。

**让成员节点也参与跨域 min，靠 `coverage` 折算**：等价于把并联公式摊平到 min 里，但会重复计算同一份不确定性，见上文第 4 点的实测反例。

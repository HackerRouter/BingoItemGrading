# 设计：动作、供给曲线与路线竞争

本文回答「平行的多条获取路线怎么算」。串联（配方、熔炼、多输入）是相加，这一点没有争议；
难点在平行：同一件物品有多个来源、同一段路能同时拿到几样东西、便宜的来源有产能上限。

## 一、把「来源」表示成动作

一个**动作**是四元组：

| 字段 | 含义 | 数据来源 |
|---|---|---|
| `cost` | 做一次的成本（TU） | 挖掘代价 / 旅行+开箱 / 交易折算 |
| `yield` | 做一次产出的**向量**（物品 → 件数） | `loot_expectation.per_trigger_expected`、`trade_offer.offers`、`structure_content.loot_tables_per_start` |
| `capacity` | 最多能做几次 | 交易 `max_uses`；挖掘默认无上限；结构 `containers_per_start` |
| `prereq` | 必须先满足的动作 | 图上的前置（工具、维度、站点） |

「产出是向量」不是形式主义：挖一块矿同时出石头、开一个箱子同时出五六种物品，
**这些产出不该各付一次旅行成本**。所以成本挂在动作上，按「要几次」计，而不是按物品计。

## 二、供给曲线

对每个物品定义

```
f(n) = 取得 n 个单位的最小成本
```

它是**凸的分段线性函数**：先用最便宜的动作，用满容量再换下一个。
这条曲线就是「竞争」的全部实现——便宜的动作先用，贵的只在便宜的不够时上场。

- **交易四条等价**（甜菜根 15 / 小麦 20 / 胡萝卜 22 / 马铃薯 26）→ 四条曲线，
  每条容量 `max_uses × gives.count`；按「每单位绿宝石的成本」升序合并。
  输入物品本身取不到（比如马铃薯没来源）的那条直接是 `∞`，自然被淘汰。
- **挖掘 vs 交易 vs 下界** → 三条曲线取最小，不需要特殊规则。

### OR 要分两种，不能一律取最小

之前这里写的是「不要用调和平均」，理由是「它假设同时走所有路，把便宜的路稀释」。
**这个理由只对了一半**：调和平均确实不适合「玩家选一条路」，但它正是
「玩家不知道会先碰到哪个」的正确模型。两种情况必须分开：

| | 语义 | 算法 | 例 |
|---|---|---|---|
| **互斥** | 玩家选一条，其余不会被走 | 取最小（曲线合并） | 进下界：黑曜石框 / 岩浆浇铸 / 修废弃门 |
| **并行** | 玩家沿一条路线跑，碰到哪个算哪个 | 速率相加 `1/μ = Σ1/μᵢ` | 跑图时遇村庄翻箱 / 遇废弃传送门开箱 |

两条各 10 / 20 分钟时：互斥 = 10，并行 = 6.67，差 33%。用错会系统性高估。

判定依据只有一条：**玩家能不能提前决定走哪条**。能决定就是互斥，
只能「走看看碰到什么」就是并行。所以它是个**语义标量**，要人工标
（`Action.race = "<组名>"`），不能从数据里推。

并行组的两条限制：

- 成员前置必须一致，否则速率相加会把共享前置重复计一次（会报错）；
- `race` 动作**不参与 Pareto 剪枝**：并行语义下「更贵」不等于「更差」，
  贵的那条仍在提供一份额外速率，按单独成本判支配会把并行收益删掉。

资源容量用完后的尾巴（快的先耗尽、只剩慢的）目前按「容量相加 + 长期平均速率」近似，
对单件和少量需求够用，报告里要标出来。

## 三、四条聚合规则

1. **OR·互斥（同一物品的多个可选动作）→ 合并曲线**
   按边际成本升序拼接，容量相加。单物品、无共享前置时，结果与「按单价排序贪心」完全一致；
   有容量上限时自然体现「先用便宜的」。
2. **AND（配方、需要多件不同物品）→ 串联变换**
   `f_child(n) = f_parent(ceil(n / ratio)) + fixed`（配方产量 ratio、熔炼固定时间、旅行固定成本）。
   多个输入 → 各自曲线相加；**同一动作只付一次**（见下条）。
3. **联合产出 → 按最大比例放大**
   同一动作出 A 与 B，需要 `(n_A, n_B)` 时次数取 `max(n_A / y_A, n_B / y_B)`，
   不是两个独立成本相加。
4. **OR·并行（同组 `race`）→ 速率相加**
   `1/μ = Σ1/μᵢ`，合并成一段，容量相加。与第 1 条的区别只在语义，不在算法复杂度：
   并行时各来源同时在跑，时间取 max 而不是 sum，所以**不能把成员的成本累加**。

## 四、共享前置只付一次

两个分支都要「去一趟村庄」时，不能各付一次旅行。做法：解出一个候选方案后，
把方案里的动作按 `(类型, 对象)` 去重，需求次数取 `max`，再计总成本。
这是「内部小绕路被消除」的另一半机制：绕路往往带来重复前置，去重后更贵，于是被淘汰。

## 五、剪枝（绕路为什么会被消除）

在合并曲线之前先做 Pareto 剪枝。动作 `a` 被 `b` 支配，当且仅当：

- `b.cost / b.yield_i ≤ a.cost / a.yield_i`（每件都更便宜），且
- `b.capacity ≥ a.capacity`，且
- `b.prereq ⊆ a.prereq`（不要求更多前置）

被支配的动作不进曲线。于是任何「更贵、产能更小、前置更多」的绕路在结构上就不可能出现在解里，
不需要等数值比较。

## 六、输出：若干条路线

解不是单个数字，而是：

1. **主路线**：`argmin f(n)`，即曲线上第一段（可能跨几段）；
2. **备选路线**：曲线上的其余段（「便宜的那条用完了」时的替代），以及把主路线里
   某个动作换成次优动作得到的变体；
3. **交叉点**：段与段的交界处就是「数量超过多少就换路线」，例如「要 3 个以下挖矿更快，
   超过 3 个去村庄更划算」。

这样「最终得到若干条不同路线、内部小绕路被竞争消除」是同一个机制的两种读法：
段来自竞争，绕路被剪枝与去重消掉。

## 八、判据

1. 单物品无耦合时，曲线解 = 按单价排序的贪心解（可直接对照）。
2. `farmer/1` 的四条等价报价 → 曲线应有 4 段，单价升序；输入不可得的那段为 `∞`。
3. 人为注入一条「更贵 + 产能更小 + 前置更多」的假来源，解与主路线不变（剪枝生效）。
4. 人为把某条便宜来源的 `capacity` 改成 1，解应在第 2 件时切到次优段（容量生效）。
5. 同一个 `once` 前置在方案里只计一次；`per_use` 随次数线性增长。
6. 去下界的成本能拆成「入口装备（一次性）+ 旅行 + 目标物品」。

## 九、尚未解决

- 多物品之间存在**耦合需求**（同一动作同时出 A 与 B）时，贪心不再严格最优；需要小规模 LP
  或按「主物品 + 副产品抵扣」近似。当前规模（单目标物品、需求 ≤ 十几个）下贪心够用，
  但要写明这是近似。

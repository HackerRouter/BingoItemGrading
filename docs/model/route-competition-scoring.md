# 路线评分与顺序约束

章节号与 [`route-competition.md`](route-competition.md) 连续。

## 十、方差与评分：用「尾部成本的分数」，不做加权多维

当前实现只有平均成本这一维。下面描述的尾部维度尚未落地：`loot/expect.py` 只传播一阶矩，`Segment` / `Curve` 也没有方差字段。

### 为什么方差不能乘进成本

现在 `units.VARIANCE_PENALTY = {low:1.0, medium:1.2, high:1.5}` 是把风险折算成一个乘法系数。
它有两个问题：三个数字是拍的；而且它把「期望成本」和「风险」压成一维，两条路线
（便宜但很飘 / 稍贵但稳定）在 Bingo 里的差别被抹掉了。

### 方差从哪来（先说能不能算）

两个来源，性质不同：

1. **单次产出的随机性**：池的 `rolls` 分布、条目权重、`set_count` 的均匀/二项分布。
   **可以算**——`loot/expect.py` 现在只传播一阶矩（期望），补上二阶矩即可得到方差，
   不需要任何新数据。
2. **产能不足导致的切换**：便宜来源用完后必须转向更贵的段。供给曲线的段边界就是这件事，
   风险表现为「在第 n 件上出现成本跳变」，不是平滑的方差。

第 2 条说明：**风险应该定义在曲线上，而不是乘在结果上**。

### 评分：两个同量纲的输出，取主导维度

不要加权和（权重无从论证），也不要单一标量（信息丢失）。做法是：

```
cost_score = clamp(round(log2(E / SCORE_FLOOR) × SCORE_STEP), 0, 30)
tail_score = clamp(round(log2(p95 / SCORE_FLOOR) × SCORE_STEP), 0, 30)   # 同样的换算
score      = max(cost_score, tail_score)
```

- `p95` 是「凑够 n 件的成本」的 95% 分位，来自曲线的段分布（含切换风险）。
- 两者**同一个量纲**（都以 TU 为底取 log2），所以 `max` 有意义：
  「最卡人的那一维决定难度」——要么平均就贵，要么有 5% 概率贵得多。
- 分布窄时 `p95 ≈ E`，两个分数几乎相同；分布宽时尾部分数抬头，正好取代现在的乘法惩罚。
- 报告里两个分数**并列输出**，并给出 `p95/E` 比值，供人判断是「稳定地贵」还是「可能很难」。

换成这条路后，`VARIANCE_PENALTY` 只在**拿不到方差**时作为退路，且应标成 `calibration`；
数据面补齐方差后它不再参与评分。

### 前置维度怎么办

前置**不是**分数维度，但也**不是**可行性门槛：工具、站点、点燃物都是物品，有自己的供给曲线。
详见下一节。

## 十一、前置是物品，只是付一次

工具、站点、维度入口本质都是「必须先拿到的一件东西」。它们**不进分数维度**，
而是进成本：拿到它的代价是 `f_X(用量)`，用量由它被用了几次决定。

### 动作的前置带 "模式"

```
requires: [(item, qty, mode)]      mode ∈ {once, per_use}
```

- `once`（工具、站点、点火源里的打火石）：同一个方案里只付一次，与用几次无关。
  这就是「一次性成本」的实现方式，不需要额外概念。
- `per_use`（燃料、火焰弹这类消耗品）：按动作次数乘。
- 共享去重（§四）对两者都生效：两个分支都要铁锚时，只付一次 `f_iron_pickaxe(1)`。

不模拟耐久：一把镐子不按「能挖多少块」衰减，所以工具永远是 `once`。
工具等级则是**硬约束**（钻石矿需要铁镐），作为必需前置建模，价格仍然过曲线。

### 例：去下界不是一个「域」，是一张子图

| 需要的东西 | 来源（各自曲线） |
|---|---|
| 黑曜石 ×10 | 挖（需钻石镐） / 废弃传送门箱子的战利品 / **岩浆浇铸（铁桶，不要镐）** |
| 岩浆 | 地表岩浆湖 / 下挖到岩浆海（深度代价不同） |
| 水 | 水桶（需铁桶） / 冰融化；水本身无限，只算桶 |
| 点燃 | 打火石（铁锭 + 燧石） / 火焰弹（火药 + 烈焰粉 + 煤） |

于是「走岩浆湖还是下挖找岩浆海」「黑曜石是挖还是浇」都是 **lava / obsidian 的供给
曲线上的段**，而不是特殊规则。

### 后果：`domain` 降级

`domain`（地表 / 地下 / 下界 / 末地）不再是计算维度，只当**报告标签**用：
维度差异已经由「哪些物品在该处有来源」表达（下界的金矿只能在下界挖），
入口代价又已经进了物品曲线（黑曜石 + 点燃物）。跨域取 min 也就退化成普通的 OR。

当下两条路线（红石 / 金锭）的数字**会因为入口成本而变**：现在下界路线只算了一次
「找废弃传送门」的旅行（2.57 TU），没有算黑曜石与点燃物；按新模型它会变贵。
这是预期中的修正，不是回归。

### 十一的判据

1. 同一个 `once` 前置在方案里出现两次，只计一次。
2. `per_use` 前置的数量随动作次数线性增长。
3. 把黑曜石改成「浇铸」而不是「挖」，主路线不变但成本变化，且 `provenance` 能指出用了哪段曲线。
4. 去下界的总成本能拆成：入口装备（一次性）+ 旅行 + 目标物品本身的成本。

### 十的判据

1. `loot/expect.py` 对同一张表能同时给 `E` 与 `sd`；对确定性的表（单条目、定数）`sd == 0`。
2. 两条路线 `E` 相同、`sd` 不同 → `cost_score` 相同、`score` 不同，且差值等于
   `log2(p95 之比)` 取整。
3. 现有两条路线的 `E` 不变（补方差只增加输出，不改变期望）。

# 覆盖与精度缺口

条目编号与 [`gap-register.md`](gap-register.md) 连续。

### 1.3 覆盖缺口（P2）

**S1 · 缺结构间距的集合** —— 只剩 `desert_well`。

`pillager_outpost` **不是缺口**：`structure_density` 里一直有它，叫
`minecraft:pillager_outposts`（复数），而 `structure_sets.toml` 的前缀映射已经写对了。
之前报「缺结构密度」是因为拿**变体名**去查了**集合名**的键，已经修好。

`desert_well` 确实缺：`desert_wells` 不在那 22 条 `structure_density` 里。
它生成得很少（每群系几百个区块才一处），采集时经常一个样本都碰不到——
不是采集器坏了，是样本本身稀疏。没样本就走不了「体积占比法」（
`_search_cost` 需要 `[feature_volumes]`），所以这条路目前缺席。

**S2 · 方块/生物交互类来源（全部已补）**

四类都接上了，成本模型各不相同：

| 来源 | 做法 | 结果 |
|---|---|---|
| 痟鱼/抓生物 | `code/mob_buckets` + `biome_patch` 面积占比算「找水」 | 鱼桶 2.88–3.87 |
| 剪羊毛 | `shear` 触发（掉落表已有 2.0/次）+ 羊的密度 | `white_wool` 5.57（1~3 个改走杀羊 2.21/个） |
| 挤奶 | `bridge/entity_behaviour`：容器对生物用一下 | `milk_bucket` 3.40 |
| 取蜜 | 蜂巢的区块密度 → 搜索距离；玻璃瓶对蜂巢 | `honey_bottle` 152.89 → 4.85 |

**取蜜这条暴露了一个导入器 bug**：`HISTOGRAM_MIN_PER_CHUNK` 原来是 0.01，
把 `bee_nest`（森林实测 0.00213/区块、汇总到维度级 0.0048）直接滤掉了，
于是「取蜜」只能走「一趟试炼大厅」的箱子路线。0.01 挡的是「几千区块挖一块」
那种没路线意义的东西，而蜂巢是「林子里走一圈就能看到」——两者量级不同。
阈值降到 **1e-4** 后 `block_density` 从 591 涨到 772 行。

**代价**：新增 181 个罕见方块让候选集变化，`coal` 2.68 → 3.00（+12%）、
`nether_star` +1.4%。方向是变贵（保守），换 32 倍的取蜜改善，值得。

**洞穴水体仍然缺**：美西螈（`lush_caves`）与硫磺方块（`sulfur_caves`）的桶，
表面积占比法回答不了「怎么下去」，现在直接报缺口，不给拍脑袋的数。

**S3 · 模板物品绑定** —— `binding:template-item:<容器>:<物品>`，上游只说了
「某个模板里放了这个容器」，没有表名（体检里 56 次）。属 R4 / R7 范畴。

### 1.4 精度（P3）

**A1 · `p95` / 二阶矩** —— `docs/design-route-competition.md` 第十节把评分定成
`max(cost_score, tail_score)`，现在只有前半。`loot/expect.py` 只传播一阶矩，
补二阶矩不需要任何新数据。对 Bingo 这种限时对抗，方差本身就是难度。

**A2 · 时间门与任务切换** —— 20 秒切换、被动等待 0.3 系数，都没有。

**A3 · 分层来源的层内代价**（2026-11-14 已补经验模型）

袭击已按波次累加、交易已按**经验**累计（见 `covered-register.md`），沿阶差走：
1～5 级累计 0 / 10 / 70 / 150 / 250，每级反复成交该级报价直到补满档差，
次数受 `max_uses` 限制。升级成本走 `once` 的等级能力，买第二件不再重付。
卖货换绿宝石的报价记**负**需求，卖来的绿宝石直接抵扣。

剩下的偏向只有两条，量级都在 20 TU 内：

- 卖货的绿宝石**净额为正**（卖多了有富余）时，多出来的部分被丢掉——
  模型不支持负成本，所以「靠卖货刷绿宝石」这条路没有计入。
- 升级用哪条报价由引擎比价，但同一条报价刷满 `max_uses` 后不接续下一条
  （需要跨报价凑档差时，那条候选会被跳过）。

**仍未建模**：`level: null` 的流浪商人报价只有来源、没有「遭遇频率」，
走的是 `capability:wandering_trader` 这个故意不造来源的能力，路线会被判不可达。

### 1.5 并行来源未建模（P2）

**R1 · 同一次跑图顺路拿到多个来源，全部按「专程跑一趟」计价。**

`Action.race` 与 `plan/supply.py::merge_race` 都在，测试也覆盖，但自动拼图从不给 `Action.race` 赋值：生产代码里 `race=` 只出现在工厂函数的参数透传上，没有调用方传组名。唯一用过它的是已删除的手写案例（村庄箱与废弃传送门箱并行）。

**后果**：方向是**高估**。跑图时「碰到村庄就翻箱、碰到废弃传送门就开」被拆成两趟，两笔行程各收一次；结构重叠（村庄压地牢、古城穿矿道）同理。

**为什么不能靠命名推**：并行关系取决于空间邻接，即哪些起点落在同一路线带内，不是来源属性。`structure_density` 只给最近距离，不给「两个集合是否常同时遇到」。

**恢复条件**：上游给出结构重叠对或联合出现频率（见 [`upstream-requirements.md`](../contracts/upstream-requirements.md) 第 1 条的重叠部分）；在那之前不手填 `race` 组名，避免用假设替代测量。

**影响**：涉及所有跑图型来源（开箱、结构方块、刷怪）。当前无量化，因为无法区分「真的远」与「被多收了一趟」。
